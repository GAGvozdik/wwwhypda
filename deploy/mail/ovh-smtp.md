# OVHcloud Zimbra Starter: локальная подготовка SMTP

Ящик support@wwhypdatestdeployversion.it создан, Webmail и SPF/DKIM/DMARC проверены по сообщению владельца. Отправка из приложения и deployment на VPS в этой задаче не проверялись.

## Настройки владельца

В wwwhypda-backend/env.dev для локального SMTP и отдельно в env.prod для будущего согласованного deployment:

```dotenv
MAIL_SERVER=smtp.mail.ovh.net
MAIL_PORT=465
MAIL_USE_SSL=True
MAIL_USE_TLS=False
MAIL_USERNAME=support@wwhypdatestdeployversion.it
MAIL_PASSWORD=<пароль ящика, вводит владелец>
MAIL_DEFAULT_SENDER=support@wwhypdatestdeployversion.it
MAIL_DELIVERY_MODE=smtp
MAIL_SUPPRESS_SEND=False
```

Это существующие переменные, не SMTP_HOST/SMTP_USERNAME. Не заменять весь env этим примером. Пароль не добавлять в Git. Агент env-файлы не открывал и не изменял.

MAIL_USE_SSL включает TLS сразу при подключении к 465; MAIL_USE_TLS означает STARTTLS и для этого режима False. Обе опции одновременно запрещены. Sender совпадает с авторизованным ящиком. Пустые SMTP credentials и неверные OVH-настройки останавливают запуск; ошибка не раскрывает значения настроек.

Для локальной разработки без доставки выбрать MAIL_DELIVERY_MODE=log: адреса, коды и тела писем не журналируются. Это не резервный SMTP. В smtp-режиме OVH MAIL_SUPPRESS_SEND должен быть False, иначе запуск отклоняется вместо молчаливого пропуска доставки.

## Реализация

Flask-Mail 0.10.0 сохранён. smtp_transport.VerifiedMail использует SSLContext с CERT_REQUIRED и check_hostname для SSL и STARTTLS, timeout 3 секунды, без SMTP debug. Единственный host берётся из конфигурации: fallback на Gmail или plaintext после ошибки отсутствует. В исходном Python-коде резервного Gmail SMTP также не обнаружено; активный host из env агент не проверял.

Регистрация, восстановление, JWT/CSRF, БД и тексты писем не изменены. Сохраняются supervised sender, общий deadline и response budget, число sender slots. Работа Google reCAPTCHA от смены SMTP не меняется.

Реальное письмо из приложения не отправлялось. Следующий отдельно разрешённый smoke test — доставка из dev на контролируемый адрес; затем будущий deployment и проверка с VPS. Webmail-проверка не подтверждает работу backend/его сетевого доступа.

## IMAP и оставшиеся вопросы

IMAP imap.mail.ovh.net:993 SSL/TLS нужен почтовому клиенту/работе с папками, а не отправке SMTP. В backend IMAP не добавлен. SMTP не выполняет IMAP APPEND в Sent; фактическое сохранение копий самим сервисом нужно проверить, не создавая дополнительных копий наугад.

Автоудаление, сроки email-backup/logs, перенос старых обращений и замена публичного контакта/политик остаются отдельной работой. Очистка Gmail не распространяется на OVH. Публичные контакты в этом цикле не изменены; подготовка кода не означает завершения миграции и юридическую приёмку сайта.

## Документы владельца

Источник — родительская папка mail docks: aed3211-Zimbra-IT-1.0.pdf (20.01.2025, 8 страниц) и ec8776e-OVH_Data_Protection_Agreement-IT-8.0.pdf (42 страницы; изучены относящиеся к задаче положения о расположении/субобработчиках/удалении).

Zimbra, раздел 3: технические backups не являются услугой сохранения писем клиента; конкретный email-backup retention здесь не установлен. Раздел 6: 15 дней относятся к хранению после завершения услуги, а не обычному удалению письма. Раздел 7: отдельные исходящие, обнаруженные как вредоносные/spam, хранятся год/12 месяцев — не все исходящие письма. DPA, разделы 6–10: обработка, субобработчики, обязанности и завершение услуги, а не готовая очистка Sent. Подтверждение 24 часов для VPS backup к почте не относится. Наличие DPA само по себе не подтверждает соблюдение всех требований сайта.
