# Цель

При 100% три блока Search заполняют доступную высоту окна с небольшим нижним отступом; при увеличении browser zoom ограничены высотой окна, при уменьшении — становятся ниже, как ограниченная по ширине область; внутренние переходы сохраняют оболочку интерфейса на экране, без пустого кадра и светло-бежевой вспышки в тёмной теме. reCAPTCHA сохраняет серверную проверку и ограничение обработки выбранными действиями/страницами.

## Объём и ограничения

- Только локальная реализация и проверки. Не трогать VPS, DNS, реальные письма, секреты, production-данные; не выполнять commit/push.
- Пользователь подтвердил: высота Search ведёт себя неправильно; дерево на сервере работает нормально, локально наблюдались двойной клик для раскрытия и сброс раскрытия. Дерево сначала диагностировать, не объявлять неисправным в production.
- Последнее уточнение пользователя: одного правильного цвета пустого экрана недостаточно — при внутренних переходах интерфейс вообще не должен исчезать. Это разрешает заменить нынешний механизм reload на границе CAPTCHA; гарантии ограничения Google-контекста сохраняются. Просто удалить reload и оставить Google в основном документе нельзя.
- Не менять backend/API, серверные лимиты, auth-правила цикла 004, сроки хранения, SMTP, AG Grid Community, права и структуру научных данных. Общую оболочку, CAPTCHA lifecycle и применение темы менять только в объёме этой задачи.
- Сохранять Redux и localStorage, включая черновики; комментарии и закомментированный код не удалять. Новая отдельная система тем и UI-библиотека не нужны.

## Что установлено чтением кода

- Search: `src/components/search/searchStyles.module.scss` задаёт `--search-panel-height: max(36rem, calc(100dvh - ...))`; широкий layout и дерево используют эту высоту. Это вероятная причина компенсации zoom высотой viewport, а не проверенный браузерный диагноз.
- `src/App.tsx`: при пересечении границы `requiresRecaptcha` возвращается `null`, затем вызывается `window.location.reload()`. Это конкретный источник исчезновения всего React-интерфейса. Перезагрузка введена для удаления scripts/frames/timers Google из предыдущего документа.
- Тема по умолчанию тёмная (`redux/store.ts`), но `.dark` применяется в `MainWindow` через `useLayoutEffect` после загрузки React. В `index.html` нет раннего восстановления темы; начальные переменные палитры светлые. Нужна проверка первых кадров, а не предположение об исправлении через CSS одного loader.
- Фактическая браузерная проверка архитектором не выполнена. Результаты реализации записывает имплементатор.

### Уточнение пользователя — revision 2

После проверки новой сборки пользователь подтвердил реальный поиск, отсутствие
Google до действия/после ухода и непрерывность оболочки: «ага всё работает нормально».
Для визуальной группы: «так всё хорошо, кроме того, что там блоки недостаточно
высоки», нужен небольшой отступ до низа при default на разных экранах. Затем
попросил увеличить боковой padding формы и опустить Search. На уточнение zoom:
«при увеличении они должны помещаться в высоту окна, а при уменьшении становиться
меньше окна по высоте как ширина себя ведёт». Эти прямые требования заменяют
исходное условие фиксированных 36rem/роста при zoom. Revision увеличен имплементатором
только для записи порученного уточнения, остальные ограничения не расширены.

Решение: scoped rem limit из outerHeight/корневого font-size плюс CSS viewport cap,
общая высота wide панелей. Browser zoom/DPR не угадывается. На сложенной раскладке
каждый блок ограничен viewport, вся вертикальная последовательность прокручивается.
Для совсем низких окон остаётся минимум 8rem и внешний scroll, без обрезания
управления; не обещается невозможное размещение всех элементов в произвольно малом
окне. outerHeight — метрика браузерного окна с chrome, поэтому момент перехода к
rem limit при уменьшении zoom зависит от размеров chrome; реальные Ctrl+/- и resize
ещё требуют приёмки. Padding формы 1rem/1.5rem, кнопка внизу flex-form, прокрутка
только списка параметров с fallback внешней прокруткой; дерево по поведению не менялось.
