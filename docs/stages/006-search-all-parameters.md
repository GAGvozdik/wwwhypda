# Цель

Добавить в существующую радиогруппу Search вариант `All parameters`. Выбор конкретной породы и этого варианта возвращает все её образцы со всеми доступными измерениями/параметрами. Выбор `Generic material` и конкретного параметра возвращает измерения этого параметра по всем породам. Всё выполняется одной явной кнопкой поиска в существующей таблице.

## Объём и ограничения

- Реализация только локально; архитектор изменяет только документацию. Не выполнять VPS/DNS, реальные письма, commit/push, миграции и изменения production-данных. Серверная диагностика в чате не разрешает развёртывание этого цикла.
- Цикл 005 архивирован. Сохранить его фиксированную высоту Search 44rem, zoom/reflow, непрерывную навигацию, раннюю тему и удаляемый CAPTCHA iframe.
- Разрешено необходимое расширение Flask rocks API и запроса моделей, frontend Search, типов/словаря, тестов и описаний контракта. Изменения схемы БД для этих фильтров не нужны.
- Только публичный научный каталог Sample/Measure/Rock_type/Parameter. Не подключать InputData, users_db, профили, контакты, частные заявки или поля их авторов к публичному поиску.
- AG Grid только Community. Сохранить экспорт XLSX, сортировку, фильтры, пагинацию, темы, шрифт Afacad_Flux, Redux и черновики. Не удалять комментарии/закомментированный код.
- Не включать в цикл новую систему таблиц, server-side pagination, pivot, изменение остальных родительских узлов дерева или переработку auth/CAPTCHA.

## Текущее поведение и подтверждения

- `src/components/search/search.tsx`: `selectedValue` — number/null; один execute `search`, затем GET `/rocks/samples/{rt_id}/{selectedValue}` с `X-Recaptcha-Token`. Изменение радиокнопки и дерева само по себе не запускает поиск.
- `wwwhypda-backend/rocks/rocks_bp.py`: старый endpoint принимает только int/int; `Sample.getSamplesByRockType` фильтрует по точному key_rt, затем Measure — по одному id_par_msr. Специального режима Generic material и all parameters нет.
- Результат сейчас — плоский массив измерений; таблица генерирует колонки по ключам первой строки. Нельзя терять повторные измерения одного образца/параметра, складывая их в одно скалярное значение.
- ID и положение Generic material в рабочем каталоге не установлены из исходников. Не придумывать ID 0/-1/1 и не считать любой родительский узел запросом всех пород.
- Серверный инцидент 16.10.2026: по выводу владельца backend и db были Exited (0), Nginx сообщал `backend could not be resolved`. После `start db` и `start backend auth-code-cleanup` GET `/api/rocks/parameters` вернул HTTP 200. Это восстановление данного API; не доказательство проверки всех маршрутов/worker. Не планировать исправление схемы БД на основании прежнего 502.

## Планируемое поведение

| Выбор в дереве | Параметр | Результат |
| --- | --- | --- |
| Конкретная порода | Конкретный параметр | Все существующие измерения этого параметра для образцов именно этой породы; прежняя семантика |
| Конкретная порода | All parameters | Все образцы именно этой породы и все их измерения по всем параметрам |
| Generic material | Конкретный параметр | Все образцы каталога, имеющие измерения этого параметра, независимо от породы |
| Generic material | All parameters | Все образцы публичного каталога и все их измерения |

- Для прочих папок сохраняется прежняя точная фильтрация по выбранному rt_id, без автоматического включения потомков.
- Представление сохраняет существующую плоскую таблицу: одна строка на измерение, с идентификатором/именем образца, породой, параметром и единицами. У образца с несколькими измерениями будет несколько строк. Не усреднять, не брать первое/последнее и не удалять совпадающие значения.
- В режиме All parameters образец без измерений тоже представлен одной строкой с nullable полями измерения; отсутствующее значение не заменять нулём. При конкретном параметре такой образец не подходит.
- All parameters — отдельный режим, не запись справочника Parameter и не фиктивный числовой ID.

## Шаги

### 1. [ ] Зафиксировать типы, идентичность Generic material и контракт

- По безопасному чтению локального справочника/синтетическим fixtures определить Generic material. Его настоящую запись использовать в дереве, не создавать дубликат. Сервер распознаёт её по проверенной уникальной идентичности справочника (например, точному нормализованному имени `Generic material`, подтверждённому данными), затем по фактическому rt_id. Не доверять переданному клиентом названию и не привязываться к случайному числовому ID.
- Сохранить Redux currentRTID/currentRTName и текущие actions. Общие типы параметра, выбора `number | 'all' | null` и строки результата описать в `src/common/types.ts`, переиспользовать потребителями; не делать второй store.
- Новый единый публичный read endpoint: GET `/rocks/search?rock_type_id=<actual ID>&parameter_id=<actual ID|all>`. Снаружи Nginx добавляет `/api`. Передавать query через Axios `params`, token — существующим `X-Recaptcha-Token`, без тела GET и без секретов в URL. Generic material передаётся своим реальным rock_type_id; backend снимает ограничение по породе только для этой записи.
- Успех: HTTP 200 и JSON-массив с единым набором ключей во всех строках. Сохранить поля Measure из текущего to_dict и добавить `id_Sample`, `sample_name`, `rt_id`, `rt_name`, `param_name`, `parameter_code`, `units`, `row_id`. Для строки без измерения все поля Measure, включая id_Measure/id_par_msr, nullable. `row_id` — стабильный `measure:<id>` либо `sample:<id>:no-measure`.
- Некорректные/отсутствующие/повторные неоднозначные query-значения — 400; неизвестные корректные ID — 404; известные фильтры без результатов — 200 `[]`; ошибка БД — безопасный 500, не пустой успешный массив. Имена ошибок не раскрывают SQL/секреты. Не ослаблять CAPTCHA ради ошибок/тестов.
- Старый `/rocks/samples/<int>/<int>` сохранить совместимым по URL и прежнему формату ответа; его существующие потребители не должны получить новый неожиданный контракт.
- Приёмка: контракты и фактический способ определения Generic material записаны в журнале; нет скрытых решений о потере данных или включении потомков.

### 2. [ ] Реализовать серверный запрос всех комбинаций

- Файлы: `rocks_bp.py`, `rocks_models.py`; разрешён небольшой query helper рядом, если он удерживает ответственность моделей/endpoint понятной.
- Новый endpoint использует существующий verify_recaptcha с expected action `search` и действующие ограничения запросов. Не снимать CAPTCHA и не открывать защищённый GET `/rocks/samples` для обходного получения всего каталога. Lookups `/rock_type` и `/parameters` сохраняют текущий scope без CAPTCHA.
- Выполнять фильтрацию в БД: Sample + RockType + Measure + Parameter. В All parameters использовать outer join измерений для сохранения образцов без них; при конкретном параметре возвращать только соответствующие измерения. Для Generic material не ограничивать key_rt; для другой породы — точное равенство.
- Не выполнять отдельный запрос за каждым образцом/параметром и не запускать N поисков из браузера. Не собирать весь каталог на клиенте для последующей фильтрации. Не терять строки при joins и не использовать DISTINCT/aggregate как маскировку дубликатов.
- Упорядочить детерминированно по образцу/параметру/измерению; сохранить числовые значения, error, null и повторные измерения. Единицы и название параметра брать из справочника соответствующего измерения. Чётко ограничить сериализуемые поля контрактом шага 1.
- Не вводить молчаливый LIMIT и не обещать «все» при усечённом ответе. Проверить план/число запросов на синтетическом каталоге большего размера; если разумное выполнение требует изменения API с пагинацией, записать результат и вернуть этот же план архитектору вместо скрытого ограничения.
- Приёмка: четыре комбинации из таблицы возвращают ровно нужные строки; старая числовая ручка совместима, нет доступа к частным данным и запросов БД на каждую строку.
- Документация: синхронизировать новый API-контракт в README backend/корневом README при наличии соответствующего раздела и `docs/rules/boundaries.md` после проверки.
