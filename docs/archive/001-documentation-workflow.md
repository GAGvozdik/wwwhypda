# Цель

Перенести управление работой wwwhypda в docs: две роли, один план на цикл, отдельные правила, архив и короткая инструкция для пользователя.

Этот файл ретроспективно фиксирует первоначальную миграцию по прямому запросу пользователя. Следующие циклы начинают с плана архитектора в docs/stages и завершают переносом этого файла в архив.

## Объём

Только документация. Не менять runtime-код, UI, зависимости, VPS, env и состояние данных. Из neurobaza заимствовать принцип stages/contracts/history, но не reviewer, обязательные approval-переходы, стек и страницы другого проекта. Прямой запрос пользователя заменяет старое правило не вводить stage/archive.

## Шаги

### 1. [x] Изучить исходный процесс и сохранить историю

Прочитаны роли wwwhypda и workflow/manual/roles/stages neurobaza. Исходные роли и TASKS сохранены побайтово в docs/archive/legacy. Невыполненные задачи не объявлены завершёнными.

### 2. [x] Вынести роли и правила

Созданы docs/roles и docs/rules. Общие/frontend/API/UX/проверочные требования адаптированных прежних ролей сохранены отдельно от процесса. Устаревшее наблюдение о наличии Enterprise заменено требованием сверять актуальные Community-зависимости. Старые роли оставлены в виде указателей.

### 3. [x] Установить цикл одного плана

Созданы WORKFLOW, STATE, шаблон, каталоги stages/archive и BACKLOG. После реализации имплементатор отмечает проверки, обновляет документацию и самостоятельно архивирует этот же план. Планнер создаёт следующий цикл. Статус не дублируется в STATE.

### 4. [x] Добавить короткую инструкцию и проверить документацию

MANUAL содержит порядок работы, начальные промпты каждой роли, продолжение чатов и шаблоны коммитов. README приложения указывает docs. Проверены локальные Markdown-ссылки, ссылки rules в планах, единственность активного плана, побайтовая сохранность legacy и видимость новых файлов в Git.
