# Шпаргалка: два чата

## Как работать

1. Открой чат архитектора. Дай цель — он создаст один план в docs/stages.
2. Проверь план. Открой чат имплементатора и поручай выполнить его.
3. Имплементатор делает шаги, отмечает результат и сам переносит готовый план в docs/archive.
4. Проверь изменения и сделай коммит. За следующей задачей вернись к архитектору.

Если план меняется во время работы — уточняет архитектор в том же файле. Новый цикл начинается только после завершения прежнего.

## Первый промпт архитектору

```text
Работаем в C:/Users/gvozd/Desktop/01_programs/full_stack/32_wwwhypda/wwwhypda.
Ты — архитектор / планнер. Прочитай docs/README.md,
docs/roles/ARCHITECT_ROLE.md и следуй указанным там документам.
Составь и сохрани один план следующего цикла для цели: [МОЯ ЦЕЛЬ].
Код не меняй. Работа только локально, VPS не трогай.
```

## Первый промпт имплементатору

```text
Работаем в C:/Users/gvozd/Desktop/01_programs/full_stack/32_wwwhypda/wwwhypda.
Ты — имплементатор. Прочитай docs/README.md,
docs/roles/IMPLEMENTER_ROLE.md и следуй указанным там документам.
Выполни активный план из docs/STATE.md полностью: внеси изменения,
проверь, обнови документацию, отметь шаги и архивируй готовый план.
Работа только локально, VPS не трогай. Commit/push не выполняй.
```

## Следующее сообщение в существующем чате

Архитектору: «Предыдущий цикл архивирован. Составь новый план: [ЦЕЛЬ]».
Имплементатору: «Продолжи активный план из docs/STATE.md с первого невыполненного шага».

## Названия коммитов

- План: docs(stage-002): plan ovh email migration
- Код: fix(stage-002): configure ovh smtp
- Завершение: docs(stage-002): archive completed plan

Замени 002 на номер плана. Название описывает фактическое изменение. Для новой функции — feat, для исправления — fix, для документов — docs. В коммит включай нужные файлы этого цикла, не всё подряд. Prod-конфиги могут быть вне Git; git pull не переносит их автоматически.
